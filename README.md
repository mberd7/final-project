## ფუნქციონალი

**ყველა ვიზიტორისთვის**
- მთავარი გვერდი: პოპულარული (ყველაზე ხშირად დაჯავშნილი) და ახლახან დამატებული მანქანები, სწრაფი ძებნა
- ყველა მანქანის გვერდი დალაგებით (ფასი, წელი, სიახლე, პოპულარობა) და გვერდებად
- ძებნა: ქალაქი, გამოშვების წლები (დან–მდე), ტევადობა, თავისუფალი თარიღები — ცალ-ცალკე ან ერთად
- მანქანის გვერდი: 3 ფოტო, დეტალები, მფლობელი, რუკა (თუ კოორდინატები არის)
- რეგისტრაცია (5 ველი) და ავტორიზაცია (ტელეფონი + პაროლი)

- დაჯავშნა კალენდარში — დაკავებული დღეები გადახაზულია
- გადახდა ბარათით და ჯავშნის ქვითარი (ნომრით, ბეჭდვის შესაძლებლობით)

## მონაცემთა ბაზა

ყველა ცხრილს Django ავტომატურად უმატებს პირველად გასაღებს (**PK**) — სვეტს `id`.
გარე გასაღები (**FK**) ბაზაში ინახება როგორც `<სახელი>_id`.

| ცხრილი | გარე გასაღებები | კავშირი | რას ინახავს |
|---|---|---|---|
| `User` | — | — | ტელეფონი (შესვლისთვის, უნიკალური), სახელი, გვარი, ელ-ფოსტა, პაროლის ჰეში |
| `Car` | `owner_id` → User | User 1 : N Car | ბრენდი, მოდელი, წელი, ფასი, ტევადობა, ტრანსმისია, ქალაქი, ბაკი, 3 ფოტო, კოორდინატები |
| `Rental` | `user_id` → User, `car_id` → Car | User 1 : N, Car 1 : N | ჯავშანი: აყვანის და დაბრუნების თარიღი, ქალაქი, გადახდილი თანხა, სტატუსი |
| `Payment` | `rental_id` → Rental (უნიკალური) | Rental 1 : 1 Payment | თანხა, მფლობელი, ბარათის ტიპი, **მხოლოდ ბოლო 4 ციფრი**, სტატუსი |
| `Favorite` | `user_id` → User, `car_id` → Car | User N : M Car | მოწონებული მანქანები (ერთი წყვილი — ერთხელ) |
| `Notification` | `user_id` → User, `rental_id` → Rental | User 1 : N | შეტყობინების ტექსტი, წაკითხულია თუ არა |

- ყველა გარე გასაღები იყენებს `CASCADE`-ს: მომხმარებლის წაშლისას იშლება მისი მონაცემებიც.
- `Rental` ინახავს ქალაქს და თანხას დაჯავშნის მომენტისთვის — ფასის შეცვლა ისტორიას არ ცვლის.
- ბაზის წესი (`CheckConstraint`) არ უშვებს ჯავშანს, რომელიც მთავრდება დაწყებამდე.

`models.py`-ის შეცვლის შემდეგ:

```bash
python manage.py makemigrations
```
```bash
python manage.py migrate
```

## როგორ მუშაობს მთავარი ფუნქციები

### დაჯავშნა და ორმაგი დაჯავშნის თავიდან აცილება

ორი ჯავშანი ემთხვევა (ერთი დღე მაინც საერთო აქვთ), თუ:

```
არსებული ჯავშნის დასაწყისი <= ახლის დასასრული   და   არსებული ჯავშნის დასასრული >= ახლის დასაწყისი
```

წესი ერთხელ არის აღწერილი — `Rental.overlapping` (`models.py`) — და მოწმდება სამ ადგილას:

1. **კალენდარში** (`calendar.js`) — დაკავებული დღეები ვერ აირჩევა (მხოლოდ მოხერხებულობისთვის);
2. **ფორმაში** (`BookingForm`) — სერვერი ამოწმებს თარიღებს მიღებისას;
3. **შენახვამდე** (`_create_booking`) — კიდევ ერთხელ, `transaction.atomic()`-ის შიგნით.

გაუქმებული ჯავშნები არ ითვლება — გაუქმება დღეებს ათავისუფლებს.

### გადახდა

1. კალენდარში არჩეული თარიღები იგზავნება გადახდის გვერდზე; სერვერი ამოწმებს და ითვლის თანხას (დღეები × ფასი).
2. `PaymentForm` ამოწმებს ბარათს: 13–19 ციფრი, **Luhn-ის საკონტროლო ჯამი**, ვადა (არ არის გასული), CVC.
3. `transaction.atomic()` — ჯავშანი, გადახდა და შეტყობინება ინახება ერთად, ან საერთოდ არ ინახება.
4. ბაზაში ინახება **მხოლოდ ბარათის ტიპი და ბოლო 4 ციფრი** — სრული ნომერი და CVC არასდროს.

### პოპულარული მანქანები

ბაზა ითვლის თითოეული მანქანის გადახდილ ჯავშნებს (`Count`), ტოვებს მხოლოდ დაჯავშნილებს,
ალაგებს რაოდენობით და იღებს პირველ 4-ს.

### ძებნა, დალაგება და გვერდები

- ყოველი შევსებული ფილტრი ემატება SQL მოთხოვნას როგორც `AND`.
- „თავისუფალი თარიღების" ფილტრი გამორიცხავს მანქანებს, რომლებსაც აქვთ დამთხვევადი ჯავშანი.
- დალაგება: `?sort=price_asc` და სხვ.; გვერდები: `?page=2` (8 მანქანა ან 10 ჯავშანი გვერდზე).
- გვერდებს შორის გადასვლისას ფილტრები და დალაგება ნარჩუნდება.

### თარიღები

ბრაუზერის ჩაშენებული თარიღის ველი ფორმატს ბრაუზერის ენით არჩევს (ხშირად თვე/დღე/წელი),
ამიტომ საიტს აქვს საკუთარი ამრჩევი (`datepicker.js`) ფორმატით **დდ.თთ.წწ** (`25.12.26`).
სერვერი იღებს მხოლოდ `25.12.26`, `25.12.2026` ან `2026-12-25` ფორმატს — ამერიკულ `05/03/27`-ს უარყოფს.

## შეზღუდვები და გაუმჯობესების იდეები

**შეზღუდვები**
- გადახდა სადემონსტრაციოა — რეალური საიტი გამოიყენებდა გადახდის პროვაიდერს (მაგ. Stripe, TBC, BOG).
- ერთსა და იმავე მილიწამში გაგზავნილმა ორმა ჯავშანმა თეორიულად შეიძლება ორივემ გაიაროს შემოწმება;
  რეალურ საიტზე ამას ბაზის დონის შეზღუდვა (PostgreSQL exclusion constraint) აგვარებს.
- პროექტი მომზადებულია დეველოპმენტისთვის: ინტერნეტში გასაშვებად საჭიროა `DEBUG = False`,
  `ALLOWED_HOSTS`, საიდუმლო გასაღები გარემოს ცვლადიდან, ვებ სერვერი (gunicorn) და PostgreSQL.

**გაუმჯობესების იდეები**
- რეალური გადახდა
- შეტყობინებები ელ-ფოსტით ან SMS-ით
- განცხადების რედაქტირება
- შეფასებები და კომენტარები
- ინგლისური ვერსია
